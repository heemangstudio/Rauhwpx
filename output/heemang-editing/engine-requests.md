# hm-wasm editing requests

Inspected HeemangEngine `crates/hm-wasm/src/{lib,types,text}.rs`, `js/test/engine.test.mjs`, and the Studio-vendored `hm_wasm.d.ts`. HeemangEngine was not modified. Studio currently vendors engine commit `280497a916a7590fce1bfa7ac5ce8ad1b39516e9`.

1. Request `Receipt.changedPages: number[] | null` on the JSON results of `Doc.transact(request: string): string`, `Doc.undo(): string`, `Doc.redo(): string`, and `Doc.restore(checkpoint: number): string`. Studio needs it in `HeemangAdapter.edit/historyEdit` and CanvasView invalidation. Current fields are `contentEpoch`, `layoutEpoch`, `pageCount`, optional `caret`, `undo`, and `redo`. Proposed additive field `changedPages: number[] | null`, with zero-based indices and `null` meaning invalidate all pages. Include removed old pages after pagination changes, or document a separate removed-pages field. Return it consistently from transact/undo/redo/restore. The adapter currently clears its complete packet cache after a successful action.

2. Optional: add `Doc.markSaved(expectedEpoch: number): void` with a `STALE_EPOCH` error and no epoch/history/layout change. `Doc.serialize(markSaved)` exists, but a host must first obtain bytes with serialize(false), await a filesystem write, then acknowledge that exact epoch. The adapter checks document instance and epoch, then calls serialize(true) to mark the engine saved. This repeats serialization after a successful write. It updates the saved digest only after acknowledgement. The shell must serialize/write/acknowledge saves in order; this no-argument acknowledgement API tracks the latest serialized candidate.

3. Optional: add `TransactRequest.selection?: { anchor: Address; focus: Address; anchorAffinity: Affinity; focusAffinity: Affinity }`, `Receipt.selection?:` the same type, and `Receipt.historyId: number`. Record before/after directed selection in each native undo group; undo/redo return the restored selection and history identity. `DocState.dirty` should compare the current history identity to the saved identity. Studio consumers are `HeemangAdapter.historyEdit/editResult/state`. Native undo()/redo() omit `caret`, and state.dirty compares contentEpoch to saved_epoch, so undoing to saved content still reports native dirty. The adapter currently keeps only before/after directed selections and content identity tokens alongside engine-owned undo groups, resolves fresh caret geometry, and reports dirty from that saved content identity. Shell document state must synchronize from adapter.state().dirty after undo/redo. Content and inverse edits remain wholly engine-owned.

The base text bindings are present, subject to the required split correction below: atomic Doc.transact with expectedEpoch; insertText including newline/tab; delete spanning paragraphs for joins; split; native grapheme navigation with 8-unit controls; query paragraphs in nested lists; same-format HWP5/HWPX serialize; and engine undo/redo. No native composition API is needed by the buffered reader.

Cross-list editing is unavailable and raises EngineNotSupportedError before mutation. HWP3 opens for reading but serialize rejects it, so its adapter remains read only. Cross-format saving and rich clipboard/formatting UI are outside this slice. ParagraphInfo.text drops nontext controls; it must not be used as a wire-offset map. Deletion uses native navigate instead of reconstructing offsets from plain text.

Native untouched HWP5/HWPX serialize(false) was checked with the real vendored WASM and returned exact input bytes without changing content epoch. Adapter serialize always invokes the native serializer. Returning to a saved history position may regenerate native layout line segments; the adapter retains the saved bytes for that clean undo/redo position so a no-content save preserves the saved file identity.

4. Required for paragraph-start/end and empty-line Enter: fix `Doc.transact(request: string): string` for `EditOp = { op: "split"; at: Address; pageBreak?: boolean }` and newline-bearing `insertText`. Every empty paragraph created by the operation must have a real line advance, paginate at the body/cell boundary, and return a caret on the correct visible page. `Doc.locate({kind:"caret", position: Address})` and page packet LINE blocks must agree, including for repeated Enter at document end. Studio call sites are `HeemangAdapter.split` and newline-bearing `HeemangAdapter.replaceText`. Live reproduction on the copied `fdi_q1.hwpx`: 100 Enter actions at the last body line of section 1 advance contentEpoch from 11 to 111 while pageCount stays 9; the last six empty-paragraph LINE records all have identical y=76005 HU, height=1400 HU. This is not safe to expose as successful editing. The adapter now throws `EngineNotSupportedError("빈 문단을 만드는 Enter 조판")` before transactions that would create an empty paragraph. Splitting nonempty text into nonempty paragraphs remains enabled. Re-enable the guarded cases after this native layout/pagination gate passes. Evidence: `output/heemang-editing/engine-empty-pagination-repro.json` and `boundary-attempt.png`.

## Slice 2

Audit basis: HeemangEngine main at `70367de` (`crates/hm-wasm` contract 1). Studio's checked-in `vendor/hm-wasm` bundle and declarations are from `280497a916a7590fce1bfa7ac5ce8ad1b39516e9` per `vendor/hm-wasm/README.md`; do not treat the findings below as a claim that the main revision is already vendored or exercised by Studio. The supported slice below is verified against the unchanged vendored bundle; a main-package refresh is a separate task.

Existing in main: `Doc.transact(request: string): string` takes `{ expectedEpoch?: number; ops: EditOp[] }`, applies the supported op list as one undo unit, rejects stale epochs before mutation, increments `contentEpoch` and lays out once on success, returning a `Receipt`. The editor applies translated ops atomically; the adapter also checkpoints format-table allocations performed while translating requests. `formatChars` supports only `bold`, `italic`, `underline`, `size` (HU; 1000 = 10pt), `color` (COLORREF); `formatParas` supports only `align`, `spaceBefore`, `spaceAfter`, `left`, `indent` (HU), `lineSpacing` (percent). `insertText` has no format parameter. `Doc.query` supports only bounded paragraph lists; `ParagraphInfo` exposes plain text, wire length, caret bounds and controls, not effective formatting. `Address` is paragraph-list-relative: section + control/index steps + paragraph + UTF-16 wire offset (controls can occupy 8 units). `Doc.select` returns page-tagged rectangles but validates and selects within one list.

### Formatting and typing

- Extend the existing `CharPatch` with `strike?: boolean`, `fontFace?: string`, and `charSpacing?: number`. `strike` sets or clears the strike flag. `fontFace` assigns that family to all seven script slots, allocating/deduplicating document face-name entries and using the registered font system for rendering; reject an unresolved family before mutation. `charSpacing` is an absolute integer percentage of the base character size in `[-50, 50]`, applied to all seven script slots, rather than a delta. Keep existing bold/italic/underline/size/color behavior. Add these fields to `formatChars` so range changes remain part of the same atomic `transact` and undo group.
- Add `EditOp` variant `{ op: "applyStyle"; from: Address; to: Address; styleId: number }`. It applies a document style to all touched paragraphs in the addressed list in one transaction. Expose style metadata through the style query below; style table mutations/creation are not requested in this slice.
- Add `{ kind: "formatContext"; at: Address; to?: Address }` to `QueryRequest`. Return `FormatContext = { characters: CharPatch; paragraphs: ParaPatch; styleId: number; list: null | { kind: "bullet" | "numbering"; id: number; level: number }; mixed: string[] }`, with effective values at `at` and property paths such as `characters.bold` in `mixed` when the selected range differs. For a collapsed caret, return the insertion context chosen from the preceding character/paragraph (or paragraph defaults at its start), with a documented affinity rule. This is needed to paint toolbar state and initialize insertion marks.
- Add `format?: CharPatch` to `insertText` (and define it for replacement text in the same `transact`). Apply the patch to inserted units atomically with insertion; absent patch inherits the engine's normal insertion context. A separate UI-only caret mark must not silently mutate document state.
- Add `{ kind: "styles"; from?: number; count?: number }` and `{ kind: "style"; id: number }` query cases. Return stable IDs, names, localized names if present, paragraph/character style references, and enough style properties for Studio's picker/current-style display.
- Studio callsites: `src/command/commands/format.ts` commands `format:bold`, `format:italic`, `format:underline`, `format:strikethrough`, font controls, and style picker/dialog; `src/ui/toolbar.ts` wires formatting toolbar commands; `src/view/heemang-reader.ts` routes Heemang commands into `HeemangAdapter.formatCharacters/formatParagraphs`; `src/ui/heemang-edit-dialogs.ts` uses explicit values because no current-format query exists. Add style/context handling at those same Heemang callsites and the adapter, retaining native transaction history.

### Lists and numbering

- Add `EditOp` variant `{ op: "setList"; from: Address; to: Address; list: null | { kind: "bullet" | "numbering"; id: number; level: number; restart?: number } }`. `null` removes list formatting; setting the active same kind/id on the selected paragraphs toggles it off only if Studio explicitly requests toggle semantics (avoid implicit engine toggling). Preserve numbering IDs/level format in the document's DocInfo, support restart value, and include the result in `formatContext`.
- Add `{ kind: "lists" }` and `{ kind: "list"; listKind: "bullet" | "numbering"; id: number }` query cases exposing bullet/number definitions and numbering level formats/start numbers. Define ID allocation only if creation is needed; current Studio bullets/numbering UI chooses or ensures definitions before applying.
- Studio callsites: `src/command/commands/format.ts` `format:bullet-shape` and list/style commands; Heemang list commands currently reach the pre-mutation stub in `src/view/heemang-reader.ts`; list UI state will come from the formatting context query.

### Tables, cell selection, and geometry

- Add structural `EditOp` variants addressable by `TableAddress = { section: number; steps?: Step[]; para: number; control: number }`: `{ op: "insertTableRows"; table: TableAddress; beforeRow: number; count: number }`, `{ op: "deleteTableRows"; table: TableAddress; startRow: number; count: number }`, `{ op: "insertTableColumns"; table: TableAddress; beforeColumn: number; count: number }`, `{ op: "deleteTableColumns"; table: TableAddress; startColumn: number; count: number }`, `{ op: "mergeTableCells"; table: TableAddress; startRow: number; startColumn: number; endRow: number; endColumn: number }`, and `{ op: "splitTableCell"; table: TableAddress; row: number; column: number; rows: number; columns: number; equalRowHeight: boolean }`. Use zero-based inclusive range ends for merge; return a receipt mapping the selected/current cell and invalidated table targets after structural edits. Validate rectangular merge regions and reject invalid edits atomically. All must share `transact` undo/redo and stale-epoch semantics; do not add a parallel ungrouped mutation API.
- Add `QueryRequest` case `{ kind: "table"; table: TableAddress; page?: number }`, where `TableAddress = { section: number; steps?: Step[]; para: number; control: number }`. Return row/column counts, each cell's row/column and rowSpan/columnSpan, and its visible geometry as page-tagged `Rect[]` (a cell/table can span pages). This avoids forcing Studio to reconstruct merged-cell geometry from paint packets. Specify target remapping for cells removed or combined by edits.
- Extend selection requests with a tagged table-cell range, e.g. `{ kind: "cells"; table: TableAddress; from: { row: number; column: number }; to: { row: number; column: number }; page?: number }`; return selected cell addresses plus page-local cell rectangles, including split-page fragments. Extend copy/paste to consume that selection. Existing `{ from, to }` text select/copy/paste requires both endpoints in one paragraph list and cannot represent a rectangular multi-cell selection.
- Studio callsites: `src/command/commands/table.ts` table row/column insertion/deletion and merge/split commands; `src/view/heemang-reader.ts` pointer selection and its current cross-list guard; route engine-specific requests through `HeemangAdapter`.

### Clipboard and selection replacement

- Extend `PasteRequest` and `Doc.paste(request: string): string` to accept exactly one of `{ at: Address }` or `{ replace: { from: Address; to: Address } }`, plus `expectedEpoch?: number` and optional plain `text`. For `replace`, delete the selection and insert the engine-held fragment in one native editor transaction/undo unit, returning a caret after insertion. Reject cross-list ranges unless the table-cell selection contract above explicitly handles them. Current `paste` only inserts at `at`; Studio currently deletes/replaces through `HeemangAdapter.replaceText`, so copy/paste replacement would otherwise split into separate undo steps or lose copied formatting.
- Retain `Doc.copy(request: string): string` with JSON `{ from: Address; to: Address }` input and JSON `Copied` output and its per-Engine rich fragment. Its current fragment preserves paragraph and character shape data for text, but drops controls/tables/objects; it emits text+HTML. Clipboard is engine-owned and copy has no document epoch change. Define fragment ownership/expiry across document close and copy from another open document; the current engine-level clipboard can be used by another Doc, with face references resolved by name on cross-document paste.
- HTML import has no native implementation: `Doc.paste` accepts the engine's internal fragment or plain text only. Add `Doc.importHtml(request: string): string` with `{ html: string; at?: Address; replace?: { from: Address; to: Address }; expectedEpoch?: number }` input and `Receipt` JSON output, requiring exactly one of `at` or `replace` and applying the import atomically as one undo step. Support paragraphs, spans, font family/size, bold/italic/underline/color, line breaks and tabs; explicitly drop unsupported controls and resource references. Keep sanitization in Studio before calling it. Studio callsites: `src/command/commands/edit.ts` (`edit:copy/cut/paste`) and `src/view/heemang-reader.ts` clipboard event/menu handlers, with replacement in `HeemangAdapter.pasteText`.

### Package and verification boundary

The main checkout exposes `Doc.copy`/`paste`, selection geometry and paragraphs query, but not formatting-context/style/list/table structural/table-range/HTML-import requests above. The Studio vendored bundle at `280497a` is an older package; `HeemangAdapter` at slice 1 commit `d599e35c` reported `hasInternalClipboard() === false`. Slice 2 now uses the unchanged vendored engine's narrow internal text fragment, formatting and search APIs with explicit pre-mutation guards for the missing paths. Avoid inferring capability from source HEAD until the main crate is rebuilt and its generated `.d.ts`/WASM package is installed and adapter calls are exercised against that exact bundle.


Required clipboard preservation correction: extend `Doc.copy(request: string): string` and its internal `Fragment` schema to preserve soft line breaks, nonbreaking spaces and fixed-width spaces as their original typed units. Copy currently drops `CharControl(10)` and normalizes `CharControl(30/31)` to ordinary spaces. Preserve the units and their character formatting through internal paste, and define plain-text/HTML exports without silently losing line breaks. `HeemangAdapter.copyText/cutText` currently reject paragraphs containing these units or unaccounted wire units before changing the native clipboard or deleting content. `ParagraphInfo` needs a typed unit/wire map if safe subranges within such paragraphs should be enabled. The regression fixture is `tests/fixtures/heemang-clipboard.hwpx`.


Atomicity contract: `Doc.transact(request: string): string` and `Doc.paste(request: string): string` must roll back the complete document, including newly derived character/paragraph shapes and face-name allocations, if request translation or any editor op fails. Preserve the pre-call undo/redo stacks and content/layout epochs on failure. Studio callsites are `HeemangAdapter.checkpointed/applyEdit`; the current adapter supplies this rollback with native checkpoint/restore, which advances epochs even when content is restored.


Required same-format layout round trip: keep the signature `Doc.serialize(markSaved: boolean): Uint8Array`, and make `Engine.open(savedBytes)` reproduce the live edited document's effective text, character/paragraph properties, pagination, line positions and paint geometry under the same font files. Runtime face/glyph/resource IDs may differ and are normalized for comparison; coordinates must not. Studio callsites are `HeemangAdapter.serialize`, `src/command/save-document-format.ts`, and same-format reopen through `loadDocument/prepareFonts`. This is observed against Studio's vendored `280497a` package, not a build of current main. Real Studio gate copies preserve saved text/styles and page counts but the first changed line moves by -588 HU (-7.84 px) in `lang_exam.hwp`, -293 HU (-3.91 px) in `nikl_plan.hwp`, and -4808 HU (-64.11 px) in `fdi_q1.hwpx`. `exam_math.hwp` passes the full layout comparison. These are measured first differences, not maximum drift. Re-running `prepareFonts` on the edited nikl document leaves font requests, generation and geometry unchanged, while reopened geometry still differs. Evidence is `slice2/suite-matrix.json`, `slice2/font-diagnostic-summary.json`, and the linked native packet snapshots and before-save/reopened PNGs. Do not count the three documents as passing the full persistence-layout gate until the engine/package behavior is corrected.
