# hm-wasm editing requests

Inspected HeemangEngine `crates/hm-wasm/src/{lib,types,text}.rs`, `js/test/engine.test.mjs`, and the Studio-vendored `hm_wasm.d.ts`. HeemangEngine was not modified. Studio currently vendors engine commit `280497a916a7590fce1bfa7ac5ce8ad1b39516e9`.

1. Request `Receipt.changedPages: number[] | null` on the JSON results of `Doc.transact(request: string): string`, `Doc.undo(): string`, `Doc.redo(): string`, and `Doc.restore(checkpoint: number): string`. Studio needs it in `HeemangAdapter.edit/historyEdit` and CanvasView invalidation. Current fields are `contentEpoch`, `layoutEpoch`, `pageCount`, optional `caret`, `undo`, and `redo`. Proposed additive field `changedPages: number[] | null`, with zero-based indices and `null` meaning invalidate all pages. Include removed old pages after pagination changes, or document a separate removed-pages field. Return it consistently from transact/undo/redo/restore. The adapter currently clears its complete packet cache after a successful action.

2. Optional: add `Doc.markSaved(expectedEpoch: number): void` with a `STALE_EPOCH` error and no epoch/history/layout change. `Doc.serialize(markSaved)` exists, but a host must first obtain bytes with serialize(false), await a filesystem write, then acknowledge that exact epoch. The adapter checks document instance and epoch, then calls serialize(true) to mark the engine saved. This repeats serialization after a successful write. It updates the saved digest only after acknowledgement. The shell must serialize/write/acknowledge saves in order; this no-argument acknowledgement API tracks the latest serialized candidate.

3. Optional: add `TransactRequest.selection?: { anchor: Address; focus: Address; anchorAffinity: Affinity; focusAffinity: Affinity }`, `Receipt.selection?:` the same type, and `Receipt.historyId: number`. Record before/after directed selection in each native undo group; undo/redo return the restored selection and history identity. `DocState.dirty` should compare the current history identity to the saved identity. Studio consumers are `HeemangAdapter.historyEdit/editResult/state`. Native undo()/redo() omit `caret`, and state.dirty compares contentEpoch to saved_epoch, so undoing to saved content still reports native dirty. The adapter currently keeps only before/after directed selections and content identity tokens alongside engine-owned undo groups, resolves fresh caret geometry, and reports dirty from that saved content identity. Shell document state must synchronize from adapter.state().dirty after undo/redo. Content and inverse edits remain wholly engine-owned.

The base text bindings are present, subject to the required split correction below: atomic Doc.transact with expectedEpoch; insertText including newline/tab; delete spanning paragraphs for joins; split; native grapheme navigation with 8-unit controls; query paragraphs in nested lists; same-format HWP5/HWPX serialize; and engine undo/redo. No native composition API is needed by the buffered reader.

Cross-list editing is unavailable and raises EngineNotSupportedError before mutation. HWP3 opens for reading but serialize rejects it, so its adapter remains read only. Cross-format saving and rich clipboard/formatting UI are outside this slice. ParagraphInfo.text drops nontext controls; it must not be used as a wire-offset map. Deletion uses native navigate instead of reconstructing offsets from plain text.

Native untouched HWP5/HWPX serialize(false) was checked with the real vendored WASM and returned exact input bytes without changing content epoch. Adapter serialize always invokes the native serializer. Returning to a saved history position may regenerate native layout line segments; the adapter retains the saved bytes for that clean undo/redo position so a no-content save preserves the saved file identity.

4. Required for paragraph-start/end and empty-line Enter: fix `Doc.transact(request: string): string` for `EditOp = { op: "split"; at: Address; pageBreak?: boolean }` and newline-bearing `insertText`. Every empty paragraph created by the operation must have a real line advance, paginate at the body/cell boundary, and return a caret on the correct visible page. `Doc.locate({kind:"caret", position: Address})` and page packet LINE blocks must agree, including for repeated Enter at document end. Studio call sites are `HeemangAdapter.split` and newline-bearing `HeemangAdapter.replaceText`. Live reproduction on the copied `fdi_q1.hwpx`: 100 Enter actions at the last body line of section 1 advance contentEpoch from 11 to 111 while pageCount stays 9; the last six empty-paragraph LINE records all have identical y=76005 HU, height=1400 HU. This is not safe to expose as successful editing. The adapter now throws `EngineNotSupportedError("빈 문단을 만드는 Enter 조판")` before transactions that would create an empty paragraph. Splitting nonempty text into nonempty paragraphs remains enabled. Re-enable the guarded cases after this native layout/pagination gate passes. Evidence: `output/heemang-editing/engine-empty-pagination-repro.json` and `boundary-attempt.png`.
