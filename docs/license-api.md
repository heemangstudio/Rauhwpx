# Desktop license gate

This draft depends on the key server in [PR #490](https://github.com/heemangstudio/Rauhwpx/pull/490). The macOS launch price is ₩9,900 once, with two devices per key. Development runs are unenforced unless `HAMA_LICENSE_GATE=on`.

## Production public key required before v3.1.0

Edit **`desktop/license-lease.mjs`**, `PRODUCTION_LICENSE_PUBLIC_KEYS['hama-prod-1']`. Replace `REPLACE_WITH_PRODUCTION_ED25519_PUBLIC_KEY_BASE64` with the **raw 32-byte Ed25519 public key in base64**, exactly the `rawBase64` field returned by `GET /v1/license/public-key` on the provisioned production server. Compare it with the public key generated by the owner before committing it. Do not paste an SPKI DER key, a private key, or a signing secret.

`hama-prod-1` is the signing-key ID in the server's lease and public-key response. Activation compares the endpoint's key and ID with the configured pin; it never downloads a new trusted key. The placeholder refuses activation and grandfather activation. Buyers cannot activate v3.1.0 until this value is filled in and the app rebuilt.

## API contract

Default origin: `https://rau-credits-production.up.railway.app`.

| Request | Response |
| --- | --- |
| `GET /v1/license/public-key` | `{alg:"Ed25519", kid, rawBase64, spkiDerBase64}` |
| `POST /v1/license/activate {key,deviceId,appVersion,platform}` | `{ok:true,lease,keyId,expiresAt,devicesUsed,deviceLimit}` |
| `POST /v1/license/validate {key,deviceId}` | Same lease response |
| `POST /v1/license/deactivate {key,deviceId}` | `{ok:true,removed,devicesUsed,deviceLimit}` |
| `POST /v1/license/grandfather {installId}` | `{ok:true,key,created}` |

Errors are `{ok:false,error}`: `invalid_key` 404, `revoked` 403, `device_limit` 409, `not_activated` 404, `device_id_invalid` 400, `server_not_configured` 503. Grandfather errors include `grandfather_disabled` 403, `not_eligible` 403 and `install_id_invalid` 400. Network and server failures preserve a still-valid signed lease. Revocation immediately removes editing rights after the next successful check.

Keys have five groups of five Crockford base32 characters after `HAMA-`. Normalization matches the server: remove spaces and hyphens, uppercase, accept a missing prefix, map O to 0 and I/L to 1, validate the alphabet, then regroup.

A lease is `base64url(JSON bytes).base64url(Ed25519 signature over the ASCII bytes of the first segment)`. Payload: `{v:1,kid,keyId,keyHash,deviceId,issuedAt,expiresAt}`. Times are epoch milliseconds. `keyHash` is SHA-256 of the submitted key after uppercase and whitespace removal; the client submits and stores the canonical key above. The client checks signature, version, signing-key ID, device, license ID, key hash, timestamps and a maximum seven-day lifetime. This matches PR #490's updated contract at `7440d09c` and `/workspace/hamaeditor/license-api-contract.md`.


Grandfathering uses the existing `unique-install.json` install ID. Eligibility and cutoff are decided by the server's recorded first-seen time and platform. The client cannot grant eligibility itself. Eligible keys then go through the same pinned-key activation and two-device limit. Failed eligibility requests leave the trial unchanged and retry at launch or after 24 hours.

## Trial and read-only behavior

`userData/license.json` holds the device UUID, trial start, successful-save count, monotonic last-seen time and signed lease. The trial ends after 48 hours or three successful user saves. The ordinary HWP/HWPX/HML save and the portable `.rhwpx` archive save each close one native writable stream and invoke one native write. Recovery snapshots and version storage do not call that IPC. Cancelled and failed writes do not consume a save. The main process serializes the guard, native write and count update across windows.

Studio starts locked until it receives desktop status. Expiry disables typing, editing commands, history mutations and agent document writes, and shows a banner with an activation button. Document-specific read-only restrictions remain after activation. Native writes also check the gate, and a `LICENSE_READ_ONLY` rejection opens activation and produces a readable toast instead of a generic save-error alert.

Validation runs on every launch and every 24 hours. A one-minute wake-up timer refreshes time-based read-only state after trial or lease expiry. Offline use ends at the signed lease's expiry, at most seven days after issuance. Settings provides key entry, status, validation and device deactivation. The trial file is local and deleting it resets the trial; this is not a tamper-resistant entitlement store.

## Local verification

Use Node 22. Run `npm run setup`, `npm run build:wasm`, `npm run test:desktop`, `npm run test:ci`, Studio `tsc --noEmit`, `npm --prefix rhwp/rhwp-studio test`, and `npm --prefix rhwp/rhwp-studio run lint:css-tokens`.

For a local Electron run, start `node tests/fixtures/license-mock-server.mjs`. It generates an ephemeral Ed25519 keypair in memory and prints a test license and `HAMA_LICENSE_DEV_PUBLIC_KEY=hama-prod-1:<raw base64>`. Start Studio, then run Electron with `HAMA_LICENSE_GATE=on`, `HAMA_LICENSE_API_BASE=http://127.0.0.1:8787` and that public-key override. Packaged builds ignore the API and public-key overrides. No fixture private key is stored in the source tree.

Before launch, verify on a Mac: initial trial, three edited saves including a history archive, reopen output, 48-hour expiry, activation, offline grace, refund revocation, device limit, offline deactivation failure and successful deactivation. Verify the signed/notarized build separately. This draft does not build a release, notarize, upload or deploy anything.
